# Логи тестирования динамического масштабирования

Эта папка содержит выгрузки логов и метрик, подтверждающие корректную работу автоматического масштабирования в Kubernetes.

```
│

```

## Часть 1: Масштабирование по памяти

### Результаты
- **Начальное состояние**: 1 реплика
- **Максимальное масштабирование**: 7 реплик
- **Время масштабирования**: ~3 минуты (1→2→4→7)
- **Целевая метрика**: 80% утилизации памяти
- **Достигнутая утилизация**: 122%

### Ключевые файлы
- `summary.txt` - Полное описание результатов
- `scaling_events.txt` - Последовательность событий масштабирования
- `hpa_describe.txt` - Детальная информация о HPA с событиями

### Что демонстрируют логи
✅ HPA корректно определяет превышение порога памяти  
✅ Автоматическое создание дополнительных подов  
✅ Постепенное масштабирование (1→2→4→7)  
✅ Равномерное распределение нагрузки

## Часть 2: Масштабирование по RPS

### Результаты
- **Начальное состояние**: 1-8 реплик (зависело от предыдущей нагрузки)
- **Максимальное масштабирование**: 10 реплик (максимум)
- **Время масштабирования**: ~30-60 секунд
- **Целевая метрика**: 10 RPS на под
- **Достигнутый RPS**: 227+ (226675m)

### Ключевые файлы
- `summary.txt` - Полное описание результатов
- `scaling_events.txt` - События масштабирования
- `custom_metrics.json` - Кастомная метрика http_requests_per_second
- `prometheus_metrics.json` - Метрики из Prometheus

### Что демонстрируют логи
✅ Prometheus успешно собирает метрики от всех подов  
✅ Кастомная метрика зарегистрирована и доступна для HPA  
✅ Быстрая реакция на изменение нагрузки (30-60 секунд)  
✅ Масштабирование до максимума при высокой нагрузке  
✅ Политики масштабирования работают корректно  

---

## Сравнение подходов

| Критерий | По памяти | По RPS |
|----------|-----------|---------|
| **Время реакции** | 2-3 минуты | 30-60 секунд |
| **Точность** | Косвенная метрика | Прямая метрика нагрузки |
| **Сложность настройки** | Низкая | Высокая |
| **Дополнительные компоненты** | Нет | Prometheus, Adapter |
| **Соответствие нагрузке** | Среднее | Высокое |

## Дополнительная информация

### Для проверяющего

Все логи были собраны во время реального тестирования:
- Дата: 14 января 2026 года
- Время: 16:06 - 17:40 (МСК)
- Окружение: Minikube v1.37.0, Kubernetes v1.34.0
- Приложение: Собственное (Flask + Prometheus client)

### Технические детали

**Часть 1 (Память):**
- Metrics Server: встроенный в Minikube
- Период опроса: 15-30 секунд
- Метрика: memory (resource)

**Часть 2 (RPS):**
- Prometheus Operator: kube-prometheus-stack
- Prometheus Adapter: custom metrics
- Период опроса метрик: 15 секунд
- Формула: `sum(rate(http_requests_total[30s])) by (pod)`
