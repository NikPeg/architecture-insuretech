   - Metrics Server собирает данные о потреблении памяти каждые 15 секунд
   - HPA проверяет метрики каждые 15-30 секунд

ПРОБЛЕМЫ И ИХ РЕШЕНИЕ:
----------------------
⚠️ Проблема: В начале теста metrics-server не предоставлял метрики
   Решение: Ожидание инициализации metrics-server (~1-2 минуты)

⚠️ Проблема: Первоначальная утилизация памяти была низкой
   Решение: Генерация достаточной нагрузки (20+ параллельных процессов)

ВЫВОДЫ:
-------
✅ HPA по памяти работает корректно
✅ Масштабирование происходит автоматически при превышении порога
✅ Система эффективно распределяет нагрузку между подами
✅ Не требует дополнительных компонентов (используется встроенный metrics-server)
✅ Простая настройка и эксплуатация

ОГРАНИЧЕНИЯ:
------------
- Более медленная реакция по сравнению с масштабированием по RPS (~2-3 минуты)
- Метрика памяти не всегда напрямую коррелирует с реальной нагрузкой
- Может привести к избыточному масштабированию, если приложение постепенно потребляет больше памяти

РЕКОМЕНДАЦИИ ДЛЯ PRODUCTION:
-----------------------------
1. Использовать комбинированный подход: и по памяти, и по CPU, и по RPS
2. Настроить оповещения при достижении порогов масштабирования
3. Регулярно анализировать паттерны нагрузки и корректировать целевые значения
4. Настроить политики graceful shutdown для корректного завершения подов
